# Phase 6 — Memory Management

Memory management is another **core OS interview area**.

The OS has to manage RAM among processes while providing:

* Efficient utilization
* Isolation
* Protection
* Controlled sharing
* Address translation

---

# 20. Memory Management Fundamentals

## 20.1 Why is Memory Management Needed?

Suppose several processes are running:

```text
P1
P2
P3
P4
```

All need memory.

The OS must:

### 1. Allocate memory

Give processes memory when required.

### 2. Deallocate memory

Recover memory when processes finish.

### 3. Protect processes

P1 shouldn't arbitrarily access P2's memory.

```text
P1 memory ✗→ P2 memory
```

### 4. Translate addresses

Programs use addresses that need to be mapped to actual RAM locations.

### 5. Efficiently utilize RAM

Avoid unnecessary unused memory.

---

# 20.2 Logical Address

A **logical address** is an address generated from the perspective of the CPU/program.

It is also commonly called a **virtual address** in systems using virtual memory.

Example:

```text
CPU generates:

0x1234
```

The process thinks this is its address.

It doesn't necessarily correspond directly to a physical RAM location.

---

# 20.3 Physical Address

A **physical address** is the actual address in physical memory (RAM).

Example:

```text
Logical address
      ↓
Address translation
      ↓
Physical address
      ↓
RAM
```

---

# 20.4 Logical vs Physical Address

| Logical Address                 | Physical Address                     |
| ------------------------------- | ------------------------------------ |
| Generated by CPU/program        | Actual location in physical memory   |
| Process sees it                 | Memory hardware uses it              |
| Part of process's address space | Location in RAM                      |
| Translated by MMU               | Final address used for memory access |

### Important

With virtual memory:

```text
Program
   ↓
Virtual/Logical Address
   ↓
MMU
   ↓
Physical Address
   ↓
RAM
```

---

# 20.5 Address Binding

**Address binding** means mapping program addresses to actual memory addresses.

It can happen at different times.

Three types:

1. Compile-time
2. Load-time
3. Execution-time

---

# 20.6 Compile-Time Binding

If the exact memory location is known at compile time, the compiler can generate absolute addresses.

```text
Compile
   ↓
Absolute address generated
   ↓
Load program at that address
```

If the program's starting location changes, it may need to be recompiled.

### Key idea

> Address determined during compilation.

---

# 20.7 Load-Time Binding

If the exact address isn't known during compilation, the compiler produces relocatable code.

At load time:

```text
Program loaded
     ↓
Loader determines location
     ↓
Addresses adjusted
```

### Key idea

> Address determined when the program is loaded.

---

# 20.8 Execution-Time Binding

Address mapping can happen while the program is executing.

```text
CPU generates address
       ↓
      MMU
       ↓
Physical address
```

This is used in modern systems with virtual memory.

### Key idea

> Address mapping can occur dynamically during execution.

---

# 20.9 MMU

**MMU = Memory Management Unit**

It is hardware responsible for translating virtual/logical addresses into physical addresses.

Conceptually:

```text
CPU
 │
 │ Virtual Address
 ↓
MMU
 │
 │ Physical Address
 ↓
RAM
```

For example:

```text
Virtual address: 1000
        ↓
       MMU
        ↓
Physical address: 5000
```

The mapping depends on the memory-management mechanism being used.

---

# 20.10 Memory Protection

Memory protection prevents a process from accessing memory it shouldn't.

For example:

```text
P1 owns:
1000 - 1999

P2 owns:
2000 - 2999
```

If P1 attempts:

```text
P1 → address 2500
```

the OS/hardware can reject the access.

This protects:

* Processes from each other
* Kernel memory from user programs
* Read-only memory from modification

### Modern systems

Memory protection is largely implemented using hardware mechanisms such as:

* Page tables
* Protection bits
* Privilege levels

---

# 21. Contiguous Memory Allocation

In contiguous allocation, each process occupies **one contiguous region of physical memory**.

Example:

```text
RAM
┌───────────────┐
│ OS            │
├───────────────┤
│ Process A     │
├───────────────┤
│ Process B     │
├───────────────┤
│ Process C     │
├───────────────┤
│ Free Space    │
└───────────────┘
```

The memory allocated to each process is one continuous block.

---

# 21.1 Fixed Partitioning

Memory is divided into fixed-size partitions.

Example:

```text
RAM
┌──────────────┐
│ Partition 1  │
├──────────────┤
│ Partition 2  │
├──────────────┤
│ Partition 3  │
├──────────────┤
│ Partition 4  │
└──────────────┘
```

One process occupies a partition.

### Problem

Suppose:

```text
Partition size = 100 MB
Process size   = 60 MB
```

Then:

```text
60 MB → used
40 MB → unused
```

That unused space **inside the allocated partition** is:

> **Internal fragmentation**

---

# 21.2 Variable Partitioning

Partitions are created dynamically according to process requirements.

Example:

```text
Process A → 100 MB
Process B → 250 MB
Process C → 150 MB
```

Memory blocks are allocated accordingly.

This reduces internal fragmentation compared with fixed partitions.

But it introduces:

> **External fragmentation**

---

# 21.3 Internal Fragmentation

Internal fragmentation is wasted memory **inside an allocated block**.

Example:

```text
Allocated block = 100 MB
Process needs   = 70 MB

Unused = 30 MB
```

The 30 MB is inside the allocated block.

```text
┌────────────────────┐
│ Process = 70 MB    │
├────────────────────┤
│ Wasted = 30 MB     │
└────────────────────┘
```

That's internal fragmentation.

---

# 21.4 External Fragmentation

External fragmentation occurs when free memory exists but is divided into **small, separated holes**.

Example:

```text
RAM

P1
Free 10 MB
P2
Free 20 MB
P3
Free 15 MB
P4
```

Total free memory:

```text
10 + 20 + 15 = 45 MB
```

Suppose a process requires:

```text
40 MB contiguous
```

It cannot fit even though total free memory is 45 MB.

Why?

Because:

```text
10 MB + 20 MB + 15 MB
```

are not contiguous.

That's external fragmentation.

---

# Internal vs External Fragmentation

| Internal                                        | External                                        |
| ----------------------------------------------- | ----------------------------------------------- |
| Waste inside allocated block                    | Free space outside allocated blocks             |
| Common with fixed-size allocation               | Common with variable-size contiguous allocation |
| Process gets more memory than needed            | Free memory is split into holes                 |
| Example: 30 MB unused inside a 100 MB partition | Example: 10 + 20 + 15 MB holes                  |

### Easy memory trick

```text
Internal → inside allocated block
External → outside, between allocations
```

---

# 22. Memory Allocation Strategies

When variable-size memory allocation is used, the OS needs to decide:

> Which free block should be given to the process?

Important strategies:

1. First Fit
2. Best Fit
3. Worst Fit
4. Next Fit

---

# 22.1 First Fit

Choose the **first free block large enough**.

Suppose free blocks are:

```text
100 MB
500 MB
200 MB
300 MB
600 MB
```

Request:

```text
212 MB
```

First block large enough:

```text
500 MB
```

So allocate from 500 MB.

Remaining:

```text
500 - 212 = 288 MB
```

### Advantage

Usually fast because it stops at the first suitable block.

### Disadvantage

Can create fragmentation near the beginning of memory.

---

# 22.2 Best Fit

Choose the **smallest free block that is large enough**.

Free blocks:

```text
100 MB
500 MB
200 MB
300 MB
600 MB
```

Request:

```text
212 MB
```

Suitable blocks:

```text
500
300
600
```

Smallest suitable block:

```text
300 MB
```

Allocate there.

Remaining:

```text
300 - 212 = 88 MB
```

### Advantage

Attempts to minimize leftover space from that particular allocation.

### Disadvantage

Can create many tiny unusable holes.

Also generally requires examining many/all free blocks unless the free-list structure is optimized.

---

# 22.3 Worst Fit

Choose the **largest available block**.

Free blocks:

```text
100 MB
500 MB
200 MB
300 MB
600 MB
```

Request:

```text
212 MB
```

Largest:

```text
600 MB
```

Allocate from it.

Remaining:

```text
600 - 212 = 388 MB
```

### Idea

Leave a relatively large remaining hole that might be useful for future allocations.

### Disadvantage

Can waste large blocks and isn't generally considered the best practical strategy.

---

# 22.4 Next Fit

Next Fit is similar to First Fit, but instead of starting from the beginning of the free list every time, it starts searching from **where the previous search ended**.

Example:

```text
100
500
200
300
600
```

Suppose the previous allocation ended around the 500 MB block.

Next request:

```text
250 MB
```

Next Fit starts searching from that previous position rather than from the beginning.

If it finds:

```text
300 MB
```

it allocates there.

### Advantage

Can reduce repeated scanning of the beginning of memory.

### Difference from First Fit

```text
First Fit:
start from beginning every time

Next Fit:
start from previous search position
```

---

# Allocation Strategy Comparison

| Strategy  | Chooses                                      | Main idea                          |
| --------- | -------------------------------------------- | ---------------------------------- |
| First Fit | First block that fits                        | Fast                               |
| Best Fit  | Smallest block that fits                     | Minimize immediate leftover        |
| Worst Fit | Largest block                                | Leave large remaining hole         |
| Next Fit  | First suitable block after previous position | Continue search from last position |

### Interview note

Don't confidently claim:

> "Best Fit always produces the least fragmentation."

That's not true.

The strategies have workload-dependent behavior.

Best Fit can produce many tiny unusable holes, while First Fit often performs well in practice.

# The Core Mental Model

You should now have this progression in your head:

```text
Threads
   ↓
Shared resources
   ↓
Synchronization
   ↓
Mutex / Semaphore
   ↓
Threads can wait for resources
   ↓
Deadlock
   ↓
4 necessary conditions
   ↓
RAG
   ↓
Prevention / Avoidance / Detection / Recovery
   ↓
Banker's Algorithm
```

Then:

```text
Processes need memory
        ↓
OS manages memory
        ↓
Logical address
        ↓
MMU
        ↓
Physical address
        ↓
Memory allocation
        ↓
Contiguous allocation
        ↓
Fragmentation
        ↓
First / Best / Worst / Next Fit
```

### Three distinctions I would especially memorize

```text
Deadlock:
Everyone waits for each other.

Starvation:
One thread keeps getting denied while others progress.

Livelock:
Threads keep executing/reacting, but nobody makes useful progress.
```

and:

```text
Internal fragmentation:
Waste INSIDE an allocated block.

External fragmentation:
Free space OUTSIDE allocations, but split into holes.
```

and:

```text
Prevention:
Break a deadlock condition.

Avoidance:
Don't enter an unsafe state.

Detection:
Allow deadlock, then find it.

Recovery:
Take action after detecting it.
```

These distinctions are among the highest-value things to know for fresher OS interviews.
